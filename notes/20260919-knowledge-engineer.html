Chris 筆記｜知識工程師的崛起

原文：X · @hahnbeelee（Hahnbee Lee） · 2026-09-17

我的想法

前些日子，我剛好關注到日本 Physical AI 的發展，然後想把這個主題相關新聞與專業信息整合起來，於是就讓 Claude Code 進行規劃並整理，便明白了類似知識工程師的概念。

過去要蒐羅這樣的專業領域知識，並成為可供企業內部分享的資訊服務，這的確相當複雜。當你好不容易收集並翻譯完成後，極可能發生變化，讓你前功盡棄。尤其是更新後的信息可能會影響到之前的判斷或結論，這如果要全靠人工來整理，並且要援引依據真的得花費很多時間精力。

Nvidia 在日本與幾家機械臂大廠，合作這個 Physical AI 的計畫是7月初的時候，我讓 Claude Code 蒐集資料後，整理成一份長文報告，然後也拆解成多組 LLM wiki 詞條，就利於後續深挖不同的機械臂分類訓練資料。在判斷這個機械臂計畫後續可能遇到的問題，以及 Nvidia 在後訓練時代能發揮的作用時，皆指向日後訓練資料 datasets 的分發渠道問題，當時 AI 給了幾個判斷方向。

9月時，Nvidia 宣佈收購 Huggingface，為這則主題拋來扭轉乾坤的影響，之前撰寫的部分結論得被推翻，如果用人力去更新，真的非常痛苦。然而，這個主題的內容早已被我通過 Claude Code 用科學方法收集拆解並推上 Github ，不只能夠列出前後變化，還能說明影響的原因，這對於作知識管理的人來說，無疑是最好的方法。把這個知識工程的嘗試，推展到幾家上市公司的觀察，這能讓我提早得知股價的波動可能，比任何大師分析都還有用。當然，對於那些靠販賣投資信息的公司來說，這樣的知識工程更是助力⋯

摘要 / Summary

這篇文章談的是一個正在浮現的新職位：知識工程師（knowledge engineer）。背景是代理人（Agent）已經成為企業知識最大的受眾之一——2026 年 7 月，Mintlify 服務的技術文件中，代理人流量佔了所有可測量網頁流量的 66%。開發者請 coding agent 串接 API、買家用聊天代理人比價與下單、客戶靠客服代理人解決問題，這些代理人背後都是把「閱讀」乃至「行動」委託出去的真人。文章用 2024 年加拿大航空聊天機器人誤導顧客、最終被法庭判定要為錯誤資訊負責的案例，說明知識品質已經是營運層級的問題：一旦代理人把錯誤資訊當成權威來源接受，錯誤就會被複製進程式碼、客服回答與自動化工作流程，在成千上萬次下游互動裡不斷重演。

文章接著描繪知識工作如何從「維護頁面」轉向「維護系統」。Decagon 的 David Hou、Elastic 的 Fabrizio Ferri Benedetti、Mintlify 的 Ethan Palm 分別從產品需求、「情境策展人」定位、跨團隊資訊連結的角度描述這個轉變：知識工程師要建立權威來源與負責人、把產品發布和程式碼變更、客服工單、使用者回饋跟內容更新連結起來、以結構化頁面、Markdown、llms.txt、API 與 MCP 工具發布知識、並衡量代理人在搜尋什麼、哪些問題答不出來。文章也強調人類需求並未消失，只是變了：代理人受益於詳盡結構化的細節，人類需要的則是理解「為什麼系統這樣運作」的心智模型，細節可以交給代理人自己去找。

最後文章列出這套思維的具體好處——更新能直接從源頭流出而不必仰賴人工記憶每個下游頁面（Coinbase 把文件更新時間從 20 分鐘以上縮短到不到 60 秒）、代理人的搜尋紀錄能揭露單靠頁面瀏覽量看不到的知識落差、以及讓領域專家能把心力放在審核而非重複性草擬（HubSpot 因此把投入文件基礎建設的工程資源砍了 50%）。文章的結論是企業不必急著先創造新職稱，而是先指派責任歸屬：找到能守護知識、串接系統、衡量失靈之處的人。
